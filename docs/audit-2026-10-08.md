# ghost-rec static logic audit — 2026-10-08

Static audit of `ghost_rec.py` (no debugger, no display on the audit
machine — Linux, headless). All fixes below are in `ghost_rec.py`;
validated on Linux with stubbed `mss`/`keyboard` and the real
imageio+ffmpeg stack (22/22 checks in `/tmp/test_ghost_audit.py`,
throwaway, not committed).

## Findings and fixes

| # | Issue | Severity | Fix |
|---|-------|----------|-----|
| 1 | **Encode-finalization race.** The stop path set a stop event and `join(timeout=15)` on a writer thread sharing one global frame queue. If the join timed out, the still-live writer kept consuming the shared queue — frames from the *next* session could land in the *old* file, and the old file might never finalize. | High | Each session now gets its **own queue**, passed explicitly to its writer thread. Shutdown is **sentinel-based**: `_end_session` swaps the global queue reference to `None` under the state lock, then posts a unique `_SENTINEL` object. The writer drains everything queued before the sentinel, drains stragglers grabbed concurrently with the stop, then closes — so every queued frame is written before finalization. Abandoning a hung encoder after the timeout is now safe: it owns only its own queue and file. |
| 2 | **15s join truncation.** The old `while not done or not queue.empty()` loop could exit with frames still in flight (grab/put racing the emptiness check), silently dropping the tail of a recording; and the 15s cap could strand an unfinalized file. | Medium | Sentinel guarantees the writer only exits after draining; the join is now a hang-guard, not the finalization mechanism. Stop path joins outside the state lock (hotkeys stay responsive); `quit_app` uses a 60s timeout since that file is the keeper. |
| 3 | **Idle spin-wait.** The grab loop woke 20×/sec while idle, draining an already-empty queue. | Low | Idle branch now waits on a `_wake` event (0.25s cap) that `_start_session` sets after publishing the queue — capture starts within milliseconds of the hotkey instead of up to 250ms late. |
| 4 | **Exception-swallowing.** The grab loop caught everything, logged one line, and died — recording silently stopped mid-session. A dead writer left `_recording=True` with no session behind. | High | A `_grab_supervisor` thread restarts the capture loop with backoff (1s→2s→4s…, cap 30s) and logs each restart. A dead encoder now **auto-clears** the session state (non-blocking lock, no deadlock risk) and logs `encoder failed; recording auto-stopped`, so the next toggle starts fresh. Writer-open failure makes `_start_session` return `False` via a `ready` handshake; `toggle()` resets cleanly and logs it. |
| 5 | **Unthrottled grab loop → sped-up video** (found in audit, not in the original list). Every appended frame is stamped 1/FPS apart, but the loop grabbed as fast as `mss` allowed — a 10s recording could play back in ~4s. | High | The capture loop is now **paced to FPS** (`perf_counter` deadline per frame); slow machines drop frames instead of lagging. Verified: exactly ~60 grabs/sec in the harness. |
| 6 | **Same-second filename collision** (found in audit). Two sessions started within one second wrote to the same `ghost_<ts>.mp4`. | Medium | `_start_session` bumps to `ghost_<ts>_2.mp4`, `_3.mp4`, … when the name exists. |

Also removed the unused `import os`.

## How it was validated (Linux, headless)

- `mss` stubbed (synthetic BGRA frames; no display here), `keyboard`
  stubbed (needs root for hotkeys on Linux), **real** imageio +
  imageio-ffmpeg for true end-to-end encode/finalize.
- 22 checks: basic session decodes with all frames; back-to-back
  sessions produce independent files (18+18 frames, no mixing);
  writer-open failure recovers with `_recording` reset; grab-loop death
  restarts capture mid-session; mid-session encoder blowup auto-stops
  loudly with a finalized partial file; pacing holds 60 grabs/sec;
  quit finalizes the open session. Two real bugs in the *first* version
  of the fix (missing `global` declarations → `UnboundLocalError` in the
  writer thread's finally) were caught by the harness and fixed.
